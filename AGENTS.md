# AIDA-X — Agent & Workflow Guide

Git-backed ticket pipeline with Agent Manager worktrees. All tickets live in `/tickets/` at the repository root.

---

## Ticket Structure

```
tickets/
├── backlog/          # Unstarted work
├── active/           # In-progress (one worktree per ticket)
├── review/           # PR created, awaiting review
├── done/             # Merged/closed
└── _meta.json        # Ticket metadata (auto-managed)
```

### Ticket File Format

Each ticket is a single file: `tickets/<folder>/TICKET-NNN.md`

```markdown
---
id: TICKET-NNN
status: backlog        # backlog | active | review | done
assignee: sesch         # optional, defaults to unassigned
priority: high          # critical | high | medium | low
created: 2025-11-01
updated: 2025-11-01
---

# Ticket Title

## Description
What needs to be done and why.

## Acceptance Criteria
- [ ] Criterion 1
- [ ] Criterion 2

## Implementation Notes
Technical details, references, pitfalls.

## Checklist
- [ ] Code implemented
- [ ] Tests written
- [ ] Self-review passed
- [ ] PR created
- [ ] Merged
```

### Ticket Folders (as requested)

Group tickets into logical folders inside `/tickets/`:

```
tickets/
├── dsp/              # Audio engine, DSP, neural inference
├── ui/               # UI widgets, rendering, theming
├── plugin/           # VST3, AU, CLAP, LV2 backends
├── mobile/           # iOS, Android targets
├── web/              # WASM, WebGPU target
├── ci/               # Build system, CI/CD
└── misc/             # Everything else
```

Each folder contains ticket files like `dsp/TICKET-001.md`, `ui/TICKET-002.md`.

### `_meta.json`

Auto-generated by Kilo. Do not edit manually.

```json
{
  "ticket_counter": 42,
  "last_updated": "2025-11-01T21:00:00Z"
}
```

## Workflow Commands

All commands live in `.kilo/commands/`.

### `new-ticket.md` — Create a new ticket

```
/kilo command new-ticket "Implement iOS AUv3 wrapper"
```

Creates a ticket in `tickets/misc/TICKET-NNN.md`, sets status to `backlog`, bumps counter in `_meta.json`.

### `start-ticket.md` — Move ticket to active

```
/kilo command start-ticket TICKET-003
```

Moves file from `tickets/<folder>/backlog/` to `active/`, creates an Agent Manager worktree with the ticket as prompt, sets status to `active`.

### `create-pr.md` — Create pull request

```
/kilo command create-pr TICKET-003
```

Runs `git add`, `git commit -m "TICKET-003: ..."`, pushes branch, creates PR via `gh pr create`. Moves ticket file to `tickets/<folder>/review/`.

### `merge-ticket.md` — Close a ticket

```
/kilo command merge-ticket TICKET-003
```

Moves ticket file from `review/` to `done/`, sets status to `done`.

### `board.md` — Show ticket board

```
/kilo command board
```

Prints a table of all tickets grouped by status and folder. Shows worktree assignments.

## Agent Manager Usage

### Creating Worktrees

```python
# Create a new Agent Manager worktree for a ticket
agent_manager(
    mode="worktree",
    tasks=[{
        "name": "TICKET-003: iOS AUv3",
        "prompt": "Implement the AUv3 plugin wrapper. See tickets/active/TICKET-003.md for acceptance criteria.\n\nRules:\n- Create PR when done\n- Update ticket checklist\n- Commit with TICKET-003: prefix",
        "branchName": "ticket-003-ios-auv3"
    }]
)
```

### Managing Sessions

- **List worktrees**: `agent_manager(action="list")` — always check before moving or prompting.
- **Move to section**: `agent_manager(action="move", sessionID="ses_...", sectionID="sec_...")`.
- **Stop a session**: `agent_manager(action="stop", sessionID="ses_...")`.
- **Answer pending questions**: Use `answers` with exact label values from the question.

### Agent Selection

Use the `agent` field only when a specific agent is needed:
- **DSP work** (`aidadx_core`): default agent (strong Rust/C++ knowledge).
- **UI work** (`aidadx_ui`): default agent.
- **iOS work** (`aidadx_ios`): default agent.
- **CI/Build work** (`crates/`): default agent.

## Git Workflow

### Branch Naming

```
ticket/TICKET-NNN-short-description
```

Examples:
- `ticket/TICKET-001-dsp-core-crate`
- `ticket/TICKET-003-ios-auv3-wrapper`

### Commit Messages

```
TICKET-NNN: Conventional commit type

Body text if needed.
```

Types: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `chore`.

Examples:
```
TICKET-001: feat(dsp) add biquad filter cascade
TICKET-002: fix(ui) correct knob hit target size
TICKET-003: refactor(core) migrate model loader to candle
```

### PR Workflow

1. Agent creates worktree for ticket.
2. Agent implements changes, commits with `TICKET-NNN:` prefix.
3. Agent runs `git push --set-upstream origin branch-name`.
4. Agent creates PR: `gh pr create --base main --title "TICKET-NNN: ..." --body "See tickets/active/TICKET-NNN.md"`.
5. Kilo moves ticket to `tickets/<folder>/review/`.
6. After merge, Kilo moves ticket to `tickets/<folder>/done/`.

## Best Practices

### 1. Always Check the Ticket Board Before Starting Work

Run the board command to see what's active and avoid duplicate work.

### 2. One Worktree Per Ticket

Keep work isolated. Never mix multiple tickets in a single worktree.

### 3. Update Tickets Incrementally

As work progresses, update the ticket checklist items. Don't wait until the end.

### 4. Use Feature Flags for Platform-Specific Code

```rust
#[cfg(target_os = "ios")]
mod ios_impl { ... }

#[cfg(target_os = "macos")]
mod macos_impl { ... }
```

### 5. Test on Target Platform Early

Don't wait for the final platform to test. Use QEMU/simulators as soon as the core crate is ready.

### 6. Keep Backward Compatibility

The new Rust engine must load the same `.json` model files and `.wav`/`.flac` IRs as the current C++ version.

### 7. Document Breaking Changes

Any API change that affects the model format, state schema, or plugin interface must be logged in the ticket.
